Clone Graph

O(V + E) Time / O(V) Space

Goal: Return a deep copy of a connected undirected graph.

BFS With Original-to-Clone Map

if node == nil: return nil clones[node] = new Node(node.val) queue = [node] while queue is not empty: curr = pop queue for neighbour in curr.neighbours: if neighbour is not cloned: clones[neighbour] = new Node(neighbour.val) push neighbour clones[curr].neighbours append clones[neighbour]

Key Insight

The map answers two questions: 1. Have we already discovered this original node? 2. What clone should edges point to? Never append original neighbours into the clone. Every edge in the cloned graph must point to cloned nodes.

Course Schedule

O(V + E) Time / O(V + E) Space

Goal: Decide whether all courses can be completed given prerequisite rules.

Kahn's Algorithm: Topological Sort

Topological sort is a valid ordering of tasks where every prerequisite appears before the task that depends on it. Example: socks -> shoes Socks must come before shoes, so shoes cannot be processed until its incoming prerequisite is gone.

In-Degree Means "Prerequisites Remaining"

For Course Schedule, [a, b] means: take b before a So the graph edge is: b -> a indegree[a]++ because course a has one more prerequisite remaining.

Why Reversed Edges Still Pass canFinish

For the boolean canFinish question, edge direction does not change whether a cycle exists. If you reverse every edge, you get the transpose of the graph: 0 -> 1 -> 2 -> 0 becomes: 0 -> 2 -> 1 -> 0 Still a cycle, just in the opposite direction. So cycle detection gives the same true/false answer.

But Course Order Would Be Backwards

Topological order depends on edge direction. If [a, b] means "take b before a", the edge should be: b -> a If you accidentally build: a -> b canFinish still detects cycles correctly, but a returned course ordering would be for the reversed graph. It would come out backwards for the original prerequisite meaning.

Course Schedule II: Return the Ordering

Course Schedule I: return processed == numCourses Course Schedule II: append each popped node to res if processed != numCourses: return [] return res Because res is the actual topological order, edge direction is no longer just a cycle-detection detail. Use prerequisite -> course.

The Algorithm

1. Build graph and indegree counts. 2. Queue every node with indegree 0. These courses have no prerequisites. 3. Pop a course from the queue. 4. For each course it unlocks: indegree[neighbour]-- if indegree becomes 0, enqueue it. 5. If processed == numCourses, no cycle exists. Otherwise, some courses are stuck in a cycle.

Cycle Detection Intuition

A cycle has no valid starting point. 0 -> 1 1 -> 0 Both nodes have incoming edges, so neither ever reaches indegree 0. The queue empties before all courses are processed.

Graph Valid Tree

O(E * α(V)) Time / O(V) Space

Goal: Decide whether an undirected graph is exactly one connected, acyclic component.

Union Find View

Start with every node in its own component. For every edge (a, b): if a and b already have the same root: return false // adding this edge creates a cycle union(a, b) At the end: return numberOfComponents == 1

Why This Works

A valid tree needs both: 1. No cycles Union detects this when an edge connects two nodes already in the same component. 2. Connected All nodes must collapse into one component. If either condition fails, the graph is not a tree.

Union Find Is Not the Graph

The UnionFind parent array does NOT store graph edges. parent[x] only means: "walk upward to find this node's component representative" Union by size and path compression are free to rewrite those parent pointers however they like. The only fact UnionFind preserves is the partition of nodes into connected components.

Cycle Detection Is Local

An undirected edge (u, v) creates a cycle iff: find(u) == find(v) That means u and v were already connected by some other path before this edge arrived. This can happen long before the whole graph is connected: n = 5 edges = [[0,1], [1,2], [2,0], [3,4]] After [0,1] and [1,2], nodes 0,1,2 share a component. When [2,0] arrives, both endpoints already have the same representative, so Union returns false. At that moment there are still 3 components: {0,1,2}, {3}, {4} So cycles are not "only when everything is already one component"; they are detected inside any component.

Two Kinds of Edges

Every edge (u, v) is exactly one of these: 1. Endpoints in different components - no path exists between u and v yet - this edge is the first bridge between them - Union succeeds - nComponents drops by 1 - cannot create a cycle 2. Endpoints in the same component - some path already connects u and v - this edge is a second route between them - Union fails - nComponents stays the same - this edge closes a cycle There is no third kind of edge.

The Bridge Between UF and the Graph

UnionFind does not remember the actual path. It only remembers that a path exists. find(u) == find(v) means u and v are in the same connected component means there is already some path u -> ... -> v If you then add edge (u, v), that new direct edge closes the loop with the old path.

Tree = Acyclic and Connected

The two checks are independent: No failed union: no cycle was found nComponents == 1: all nodes are connected Tree means BOTH are true.

Alternate Shortcut

For an undirected graph: connected + no cycles <=> exactly n-1 edges So many solutions first check: len(edges) == n - 1 Then they only need to prove connectivity.

Number of Connected Components

O(E * α(V)) Time / O(V) Space

Goal: Count how many disconnected groups exist in an undirected graph.

Union Find Component Counter

Start: nComponents = n For every edge (a, b): if find(a) != find(b): union(a, b) nComponents-- Return nComponents.

Key Difference from Graph Valid Tree

Connected Components: cycles are fine duplicate connectivity just does not change the count Graph Valid Tree: cycles are not allowed if Union sees same representative, return false

Redundant Connection

O(E * α(V)) Time / O(V) Space

Goal: Return the edge that creates the cycle in an almost-tree.

Failed Union Identifies the Answer

for each edge (a, b): if union(a, b) fails: answer = edge return answer

Why Removing That Edge Works

A failed union means: a and b were already connected by another path So the new edge is redundant connectivity. It closes a cycle, but removing it leaves the old path in place, so the graph stays connected.

Why the Failed Edge Is the Last Cycle Edge

This problem guarantees: original graph = tree input graph = tree + one extra edge So there is exactly one cycle. As edges are processed in input order, every cycle edge except the last one still connects two different components. Those unions succeed because the loop is not closed yet. The final edge of that cycle is the first time its two endpoints already have the same representative. So the failed union is exactly the edge the prompt wants.

Dynamic Node Labels

This problem labels nodes from 1..n. You can use: - an array sized n+1, or - a map-backed UnionFind that lazily initializes nodes The same component logic applies either way.

Word Ladder

O(N * M^2) Time / O(N * M) Space

Goal: Find the shortest sequence of one-letter word changes from beginWord to endWord.

Bidirectional BFS With Frontiers

forwardFrontier = {beginWord} backwardFrontier = {endWord} forwardLevel = 1 backwardLevel = 1 while both frontiers are non-empty: expand the smaller frontier generate the next complete frontier if a generated word is in the opposite frontier: return forwardLevel + backwardLevel

Why Frontiers, Not Single Queue Pops?

A frontier is one distance ring. Every word inside it has the same distance from its side. That uniform distance is what makes early return safe. When the two current rings meet, the total length is well-defined. A FIFO queue can temporarily hold the tail of one level and the head of the next level. That is fine for normal BFS, but it makes bidirectional "first meeting" reasoning harder unless you track levels very carefully.

Why Expand the Smaller Side?

Expanding a frontier costs roughly: len(frontier) * wordLength * 26 So the smaller frontier is the cheaper next ring to buy. As one side grows larger, the algorithm naturally switches to the other side, keeping both waves balanced around the middle of the path.

Visited Sets Still Matter

Each side has its own visited set. visited does NOT store distance here. It only prevents one side from re-expanding the same word. The distance is tracked by the frontier-level counters.

Thoughts on the Claude Discussion

The useful critique was not "BFS is wrong." BFS is the right tool. The issue was proving correctness for bidirectional BFS. Plain BFS gives a shortest-path guarantee because nodes are processed in nondecreasing distance from one source. Bidirectional BFS needs a stronger invariant: each side's current frontier must be one synchronized ring. That is why this version keeps frontier sets instead of single-node queues. It makes the proof visible: - every forward frontier word is at forwardLevel - every backward frontier word is at backwardLevel - when the rings touch, the answer is forwardLevel + backwardLevel The frontier version is the one to keep because it is not just fast; it is easy to reason about.

What Is a Synchronized Ring?

A synchronized ring is one full BFS layer. If forwardLevel == 3, then every word in forwardFrontier is exactly 3 words away from beginWord. If backwardLevel == 4, then every word in backFrontier is exactly 4 words away from endWord. The algorithm expands one entire ring at a time and then replaces it with the next ring. That is different from thinking of "the queue" as the frontier, because a queue can temporarily contain nodes from multiple levels.

Islands and Treasure

O(m * n) Time / O(m * n) Space

Goal: Fill every traversable land cell with its distance to the nearest treasure chest.

Multi-Source BFS

queue = all treasure cells while queue is not empty: curr = pop queue for each neighbour: if neighbour is not INF: continue neighbour = curr + 1 push neighbour

Key Insight

Start BFS from every treasure chest at once. That means the first time an INF cell is reached, it is reached by the nearest treasure chest. No separate visited set is needed because updating INF to a distance marks the cell as visited.

Rotting Fruit

O(m * n) Time / O(m * n) Space

Goal: Return how many minutes it takes for all reachable fresh fruit to become rotten, or -1 if some fresh fruit can never be reached.

Multi-Source BFS With Time

queue = all rotten fruit with time 0 totalFruit = count of fresh + rotten fruit reachedFruit = 0 maxTime = 0 while queue is not empty: row, col, time = pop queue reachedFruit++ for each neighbour: if neighbour is not fresh: continue neighbour = rotten push neighbour with time + 1 maxTime = max(maxTime, time + 1) if reachedFruit != totalFruit: return -1 return maxTime

Key Difference from Islands and Treasure

Both start BFS from many sources. Islands and Treasure: update INF cells with nearest distance Rotting Fruit: update fresh cells to rotten track the latest time reached detect impossible cases when fresh fruit is isolated

Pacific Atlantic Water Flow

O(m * n) Time / O(m * n) Space

Goal: Find cells that can drain to both oceans.

Reverse the Direction

Original question: From this cell, can water flow downhill to an ocean? Easier reverse question: Starting from the ocean border, which cells can reach the ocean if we walk uphill? Pacific starts: top row + left column Atlantic starts: bottom row + right column

Meet in the Middle

Run DFS/BFS from all Pacific borders. Run DFS/BFS from all Atlantic borders. If a coordinate appears in both reachable sets, water can flow from that cell to both oceans.

Movement Rule When Reversed

Normal water flow: curr can flow to next when next <= curr Reverse search: ocean can walk to next when next >= curr That is why the DFS skips neighbours lower than the current cell.

Surrounded Regions

O(m * n) Time / O(m * n) Space worst case

Goal: Flip only the O regions that cannot reach the board border.

Boundary-Started DFS

1. Start DFS from every border O. 2. Mark all connected border-reachable O cells as T. 3. Sweep the whole board: - O -> X // trapped region - T -> O // safe region

Why This Beats Backtracking From the Inside

The tempting approach is: "Assume O is surrounded, flip it to X, then undo if a path reaches the border." That creates bugs when a component has branches: - one branch may look trapped - another branch later reaches the border - cells from the first branch can be left flipped Boundary DFS avoids guessing. If an O is reached from the border, it is safe. Everything still marked O after that is trapped.

Number of Islands

O(m * n) Time / O(m * n) Space worst case

Goal: Count connected components of land in a 2D grid. Connections are horizontal and vertical only.

Sink Land DFS

for each cell: if cell is water: continue count++ dfs(cell) dfs(row, col): if out of bounds: return if cell is water: return mark cell as water dfs(up) dfs(down) dfs(left) dfs(right)

Key Insight

The first land cell found in an island increments count. DFS then "sinks" every connected land cell by changing it from '1' to '0'. That prevents the rest of the same island from being counted again later in the outer loop.

Max Area of Island

O(m * n) Time / O(m * n) Space worst case

Goal: Find the largest connected component of land. Area is the number of cells in the island.

Same DFS, Different Accumulator

for each land cell: currArea = 0 dfs(cell) maxArea = max(maxArea, currArea) dfs(row, col): if out of bounds or water: return currArea++ mark cell as water dfs(up/down/left/right)

Key Difference from Number of Islands

Number of Islands: count how many times we start DFS from fresh land Max Area of Island: count how many cells one DFS sinks keep the largest DFS size seen
